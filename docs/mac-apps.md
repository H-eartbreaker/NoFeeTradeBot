# 双击启动和停止（Mac）

项目文件夹里有两个应用：**启动机器人.app**、**停止机器人.app**。

- 双击「启动机器人」，看到成功提示后去 Telegram 使用。不需要打开终端。
- 已运行时再双击「启动机器人」，会停止本项目旧实例并加载最新代码，不需要先打开终端。
- 提示框关闭后，后台机器人会继续运行；退出登录、关机和电脑休眠会影响运行。
- 桌面已创建「启动机器人.app」的原生替身，双击会打开项目中的应用。
- 这两个应用要留在项目文件夹里。可以把它们拖到 Dock 或在桌面放替身，不能只移动应用本身。
- 启动器不会设置开机自启，不会自动生成钱包或发交易。启动后，之前已启用的自动订单和止盈止损会照常恢复。
- 错误记录位于 `data/mac-bot.log`，私钥仍在 `.env`，不要把 `.env` 发给别人。
- 启动/停止只处理工作目录为本项目的机器人，不结束其他项目；无法确认归属时停止操作并提示，不冒险继续启动。

重建应用：开发 Agent 可执行 `zsh scripts/build-mac-apps.zsh`。生成的 `.app` 不纳入 Git，源码脚本纳入 Git。

## 启动失败修正

首次使用 launchd 任务时实际观察到退出码 78（EX_CONFIG），机器人日志为空，任务未进入启动代码。现改为应用直接用 nohup 启动后台 Node 进程；停止时兼容清理旧任务。错误弹窗会显示脚本返回的具体提示。修正后重新编译了应用。

## 代理缺失与旧进程（2026-10-29）

进一步排查确认：同项目同时有两份 Node 进程，旧终端实例有 `HTTPS_PROXY`，新桌面实例只有 `NODE_USE_ENV_PROXY=1`，因此新实例未能连上 Telegram，旧版仍在回复。已把旧进程使用的本地代理地址保存到忽略提交的 `.env`；未输出或提交私钥/Token。

应用现在使用 `restart` 操作，核对进程工作目录后停止旧实例，再带本地配置启动最新版。已完成一次实际重启与 Telegram 连通确认。若代理软件关闭或端口改变，仍需更新本地配置。
