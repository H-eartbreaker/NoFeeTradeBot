# 剩余功能实施方案（2026-10-29，用户已确认）

## 目标与边界

给本人使用的中文 Telegram 机器人补齐监控跟单、真实私有发送/费用控制、内盘，以及 Solana 自动单、盈亏和资金管理。沿用 Mac 双击启动方式、现有 Node/TypeScript、viem、Solana Kit、JSON 状态/交易账本与原有历史，不重写项目、不另起服务。用户已确认本范围，后续按独立功能验证并本地提交，不逐小步重新请求确认。

P0：五链已确认买卖监控、去重与预算跟单；已核实的 MEV 通道；Four.meme/Flap/Pump.fun 内盘；Solana 自动单/止盈止损/盈亏/转账/兑换/跨链。新增自动交易默认关闭，需用户在界面明确启用并设置预算。

P1：根据实际节点限流再接用户自选的更快 RPC/索引服务，不默认购买。P2：网页、X 社交跟单与开盘狙击沿用此前决定，暂不做；内盘交易适配不代表开盘狙击。

## 最小技术方案

- 只保留一个运行进程；复用签名队列、交易确认、余额/风控/滑点检查和账本。
- 读取公开已确认交易，约每 3 秒尝试检查；首次启用从当前高度/签名建立游标，不把历史交易当作新信号。持久化游标与事件 ID，失败保留待处理状态，不因重启重复跟单。
- 买卖识别要求目标确实签名、成功执行、存在受支持的交换行为与资产收支；陌生人转入、普通转账和无法可靠识别的交易不作为买入。多资产复杂交易不猜测。
- 跟单按目标与链单独设置买/卖开关、固定/比例金额、自己的单笔/每日/单币上限、滑点、最低目标金额。先提醒/影子运行；自动规则独立启用。预算预留和事件状态先落盘，未知交易结果不重发。
- 私有发送只使用已验证渠道，关闭时沿用普通发送。ETH 用 Flashbots Protect；BNB 用 48 Club；Solana 用 Jito 单交易 bundle 路径。保护开启而不可用时不退回公开发送；Base/Robinhood 未核实的通道显示未支持。
- 费用上限在签名/发送前核对；Jito 小费与优先费明确展示并设上限。MEV 降低风险，不能保证绝不被夹或每笔立即成交。
- 常规池继续用 Kyber/Jupiter；内盘适配基于官方公开 ABI/SDK，核对平台、合约/程序、迁移状态、最低输出、协议费与动态税。未覆盖类型明确拒绝，不能拿无滑点方法凑支持。
- Solana 补充可恢复的签名账本与真实 token/native 余额差，未知成本不伪造盈利；交易记录、盈亏、自动单与资金入口共用主菜单。SPL 与 Token-2022 分别核对程序和扩展，不盲目发送转账 Hook/保密转账等不支持指令。
- 跨链继续复用 Relay 的未签名报价与状态查询；核对来源/目标/收款人/币种/金额，Solana/EVM 各自本地签名，来源扣款不等于目标到账。

## 费用与风险

不新增订阅费、服务器、付费数据库。免费 RPC/API 可能限流，不承诺商业机器人的毫秒延迟。实际操作仍需 Gas、DEX/发射平台协议费、跨链费；启用 Jito 时另有明确设置的小费。没有机器人平台抽成。

最大风险：误把转入识别为买入、重复跟单、未知成交后重试、内盘税/迁移变化、签名/预算边界。通过严格识别、事件去重、预算预留、持久化待核对状态、发送前复查和默认关闭自动交易处理。

## 验收与交付

每一批完成后跑相关模拟测试，最后统一回归；不做重复无关检查。免费真实验证只查数据/报价/模拟/未签名构建，不使用真实钱包发送交易。不自动重启正在运行的机器人。每个完成的独立改动本地 commit，维护功能支持矩阵、测试结果和剩余限制；真实资金成交需另行指定链/代币/金额。
