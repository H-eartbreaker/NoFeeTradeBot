# 第二阶段进度

## 已完成：钱包与交易账本基础

- 旧 `PRIVATE_KEY` 保留为主钱包；新增钱包分别记录持仓、成本和规则。
- 新私钥只写入本地 `.env`，权限 0600；保存操作加锁，避免两个程序覆盖新增钱包。
- 每个钱包、每条链独立排队；同钱包同链继续串行，避免 nonce 冲突。
- 交易 hash 在等待回执之前保存到 `data/trades.jsonl`。确认超时保留待确认状态，并阻止此钱包在该链重复广播；之后只读查询回执恢复。
- 成交按 hash 去重；主流程和恢复流程都不会重复累加成本。状态或账本损坏时停止并保留文件，不自动清空。
- Gas 单独记账；Base / Robinhood 若回执未提供 L1 费，标记费用不完整，不声称是总费用。
- 不确定交易结果时自动规则暂停，避免把超时当作失败后重复卖出。

本轮验证：类型检查，35 项离线测试通过。测试使用临时目录和固定测试私钥，Telegram 与广播均被拦截。未修改真实钱包配置或正式持仓数据，未运行机器人、未花费资金。

## 已完成：钱包和交易记录菜单

- 首页增加「钱包管理」「交易记录」，命令菜单增加 `/wallets`、`/deposit`、`/history`。
- 钱包列表支持分页。详情显示各启用链余额，支持刷新和选择默认钱包，重启保留默认选择。
- 创建新钱包需确认，60 秒有效；双击、过期、取消、其他命令和重启后的旧确认不会重复创建。新钱包保留在本机，默认选择不自动改变。
- 切换默认钱包时废弃尚未执行的买入确认；旧代币卡片继续绑定其原钱包，新的 CA 使用默认钱包。
- 充值页显示当前钱包地址和可用网络，同地址在各链的余额独立。
- 导入在项目终端执行 `npm run wallet:import`，私钥输入隐藏，不接收命令行私钥参数或非交互管道，不打印私钥；导入后重启机器人再选择钱包。
- 记录按钱包和链隔离、每页五条，显示实际已记录的金额、状态、Gas 和浏览器链接。确认中/未知状态明确提示勿重复提交，L2 缺失费用不称为完整费用；不把旧版没有记录的历史当成零成本。

本轮验证：类型检查与 48 项离线测试通过。额外使用伪终端运行本地导入脚本，只访问临时测试 `.env`，确认隐藏输入和 0600 权限。未启动或重启真实机器人，未创建真实使用的钱包，未发起链上交易；Telegram 外观和真实新钱包首次交易仍待使用中核对。
