# Based Bot 个人中文版：调研与完整分期方案

调研日期：2026-10-29。状态：待用户确认的开发方案，尚未实施全部功能。

用户决定：全部功能纳入路线图，先提交完整分期方案。优先沿用已经确认的 BSC、Base、Ethereum、Robinhood Chain，再安排其余网络；只供本人使用，全中文，机器人不收平台抽成，默认使用免费 RPC。

## 1. 要解决的问题

把当前需要输入命令、固定金额按钮较多的交易机器人，完善成类似 Based Bot 的按钮式交易终端。核心场景是：选择链 → 发 CA → 核对代币与交易池 → 选择金额 → 买卖 → 管理持仓和自动订单。

第一阶段最重要的结果：不需要记命令，设置项点开后直接回复数值，买前能明确确认买的是哪条链、哪个合约和交易池。

全功能的含义分两层：

- 功能覆盖：把公开文档中的交易、钱包、订单、自动化、追踪、图表和网页终端逐步纳入。
- 实现能力：不承诺仅凭免费节点达到商业机器人的全部 DEX 覆盖、数据完整性或成交速度；每项能力按链实测后标记。

个人版保留零平台抽成。Based Bot 的推荐返佣、平台交易返现和商业客服体系不适合零抽成的单人产品，建议不搭建这些商业机制；分享链接、交易报告与盈亏卡仍纳入。该取舍需随整体方案确认，不擅自改成收费平台。

## 3. 文档中确认的产品结构

Based Bot 的主要交互不是斜杠命令，而是首页、代币监控卡片、持仓管理、订单管理和设置页面。命令只是快捷入口。[S1–S5]

- 输入 CA、池地址或支持的链接，进入代币卡片。
- 卡片内选预设买入金额，也可点自定义金额后直接回数字。
- 卖出支持预设比例、自定义比例、卖回本金和指定原生币金额。
- 设置分为全局和各链配置，可改按钮、Gas、滑点、价格影响和自动化默认值。
- 自动化包含止盈止损、移动止损、限价单、定投、跟单、开发者卖出、狙击、迁移狙击和社交跟单。[S6–S9]
- 钱包追踪包含交易/创建代币通知、过滤器、标签、持仓查看、导入导出。[S10]
- 网页终端包括 Discover、Pulse、代币详情、交易、Portfolio、Multichart、Trackers、提醒、设置和充值跨链入口。[S12–S16]

不能从文档确认的内容：其后台源码、实际节点服务、全部安全审计效果、真实平均成交速度，以及每条链每个功能的运行质量。文档不是这些能力的实测证明。

### 第 1 期：先把每天使用的 Telegram 操作做好

新增内容：

1. 首页提供买卖、持仓、钱包、订单、设置、切链和帮助入口；尚未实现的功能不显示成可交易按钮。
2. 输入 CA 后展示中文交易卡片，显示明确的链标识和完整合约地址。
3. 点买入后进入确认页；默认开启，可在设置中关闭。检测到貔貅继续禁止买入，关闭确认不代表关闭风控。
4. 确认页列出真实报价的 DEX 和池地址。多跳/拆单时标明多个池，不能把一个池假装成全部路由。
5. 检测不可用、池信息缺失、买卖税未知均写“未知/无法检测”，不写“安全”。
6. 金额、滑点、卖出比例等通过“点按钮 → 回数字”设置；支持取消、错误重填和清晰的保存反馈。
7. 设置中按链保存买卖参数与按钮；现有全局参数需有清晰的兼容方案，不能悄悄改变老仓位规则。

关键交互：确认绑定链、CA、金额、滑点和报价池，短时有效、单次使用。重复点击、过期、重启或已取消的确认不能再次下单。确认后重新核对风险和报价，池/金额等关键条件变化时重新确认。

快速买入与确认的优先级：快速买入单独显式启用；如果买前确认开启，发 CA 仍需确认，不能因快速模式绕过确认。

验收：用模拟 Telegram 更新自动测试选链、输入数值、取消、重试、确认开关、过期/重复确认、非白名单；四链只读验证，资金测试另行确定链、币与金额。

本期不做：新跟单、新狙击、新网页终端或付费节点采购。

### 第 2 期：钱包和持仓能看清、管好

- 多钱包及默认钱包；本地导入私钥，不模仿把私钥发进 Telegram 聊天的流程。
- 交易账本记录交易哈希、链、钱包、实际到账、gas、授权费和状态；区分报价与真实成交。
- 持仓分页、成本、已实现与未实现盈亏、卖回本金、指定金额卖出、盈亏图片。
- 历史数据无法补全时标记成本未知，不用余额倒推出完整历史收益。
- 提现单独确认链、币、收款地址和金额；大额/异常输入不直接发送。
- 稳定币交易及跨链先做只读报价，再加入签名执行与状态跟踪。展示来源/目标链、费用、预估到账、超时和退款状态。
- 多钱包操作先逐钱包核对余额和费用，不以一笔成功代表全部成功。

验收：余额与链上一致；买卖、授权、转账计费可核对；跨链失败/等待/到账状态明确；断线不重复转账。

### 第 3 期：完整自动订单

- 把现有止盈止损扩展为可选卖出比例、分档止盈、移动止损和单币设置。
- 新增限价买卖、按市值触发、定投和订单中心；分别配置金额、频率、次数和总预算。
- 自动订单默认不启用，由用户为每项规则明确开启；全局暂停可立即停止后续自动下单。
- 执行前检查余额、gas、滑点、流动性和有效期；原钱包/原链排队，互不相关的链不共用一个 nonce 队列。
- 保存执行状态和交易哈希；确认超时记为待确认，先查询链上结果，再决定是否补发，不能当作失败直接重买。
- 重启后恢复有效任务；漏掉的定投不默认一次性补买全部次数。

验收：目标触发、部分卖出、最高点跟踪、预算限制、取消、断线和重启恢复均可自动测试；重复事件只生成一次交易。

### 第 4 期：风控、发送方式与池子覆盖

- 每条链分别验证貔貅、买卖税、持币集中度、权限、锁池/销毁/最大交易等指标的数据来源；没有数据就是未知，审计不能保证绝对安全。
- 增加价格影响、流动性、税费过滤，以及代币/开发者黑名单。风险拦截的买卖行为分别定义，避免黑名单误阻止退出持仓。
- Gas 使用默认/自定义及总费用上限；不能给所有 L2 统一承诺“加价就更快”或“加价完全无用”。
- MEV 保护逐链验证发送渠道、覆盖范围、附加费与延迟，不把开关名称当作已经实现的保护。
- 速度模式基于阶段测速、缓存和并行优化；不承诺复制第三方“跳过所有安全检查”的极限效果。
- 保留 Kyber 作为成熟路由组件；有明确收益时才新增特定 DEX/发射平台适配器，不立即重写聚合器。
- 优先验证 BSC 的 Four.Meme / Flap、Base 的主要发射平台，以及实际使用的 ETH/RH 池。其余 DEX/发射平台按文档清单建立逐链验收表，未验收的明确标记。

验收：真实池地址和路由可核对；无流动性、税变化、错误链和风控不可用的提示正确；新增路由至少完成只读构建和对应模拟，真实成交单独验收。

### 第 5 期：钱包追踪、跟单、开发者卖出

- 追踪的钱包列表支持备注、导入导出、链/事件筛选、最低交易金额、提醒开关。
- 跟单独立配置买与卖，支持固定金额、比例模式、精确金额，互斥参数不能同时生效。
- 设置自己的单笔/每日预算上限、单币交易限制、目标成交金额与池流动性过滤。
- 明确处理目标分批卖出、重复事件、跨链收款和不由目标签名的买入；不能把陌生人向目标转币误当作目标买入。
- 开发者卖出保护仅在开发者识别与事件可靠时启用；不知道开发者时不能宣称已保护。
- 先做通知和影子运行，再验证自动交易；没有独立开启的规则只提醒，不动钱。

验收：钱包交易识别准确，通知去重；历史回放和影子运行可核对；触发到下单的延迟有实测；预算、暂停与重复事件保护有效。

### 第 6 期：狙击、迁移与社交自动化

- 指定 CA 新池狙击，按名称、符号、部署者及平台筛选的自定义狙击，迁移买入/卖出。
- 每个任务设置链、金额、预算、失效时间、过滤条件与明确的开启状态；同名币不能仅凭名称认定身份。
- X 搜索、追踪账号、CA 提取、提醒和社交跟单；Zora/Warpcast 分开验证可用的数据入口。
- 免费 RPC 可先做观察和轮询触发；高频事件、抢开盘和开发者卖出不能保证与商业基础设施同速。

验收：先用历史事件和影子运行验证误报、漏报、重复、延迟；抢单/社交自动买入需按明确的任务与小额额度单独验收。

### 第 7 期：个人中文网页终端

- Telegram 与网页共用同一个交易后端和订单状态，不复制一套签名逻辑。
- Discover：代币筛选、排序、收藏、搜索和快捷买入。
- Pulse：新币、热门币、内盘进度、迁移状态。
- 代币页：图表、价格、池、成交、风险、交易面板、持仓和订单。
- Portfolio、Multichart、钱包追踪、X 追踪、价格提醒、设置、充值和跨链入口。
- 个人登录和访问控制；默认本机/私有访问，是否公网发布另行确定。私钥不进入前端，不提供公开注册和交易分成。

验收：与 Telegram 同钱包/同链/同订单；图表时间轴与实际数据一致；网页与机器人不会重复执行同一订单；移动端可用；无后端密钥泄漏。

前端框架与图表组件到本期开工前再比较和确认，优先成熟轻量组件，不为了规划提前安装。

### 第 8 期：其余网络和平台补齐

先以四条已确定的链完成以上功能。其他 EVM 网络按实际需求排序扩展；Solana 使用单独的成熟 RPC、交易和签名组件，不能假定只添加一段 viem 配置就能支持。

Based Bot 的首页、支持网络页、跨链页网络数量和名单存在差异，不能将某链在跨链列表出现视为该链所有交易功能可用。应逐项确认网络、DEX、发射平台、风控、追踪、自动化与跨链的实际支持。

验收：每条新增链分别完成链 ID、余额、代币、买卖报价/模拟、费用、确认、订单恢复及真实小额买卖；支持矩阵逐项标记，不能一次只读测试就宣布全功能支持。

## 5. 推荐实现方式与开源复用

推荐继续现有 TypeScript + grammY + viem + Kyber 项目，逐期增加模块。不从零重写，不现在引入微服务、Redis、消息队列或新的数据库服务器。

## 6. 数据怎么流动

Telegram / 后续网页 → 本人身份校验 → 选择链、钱包与动作 → 读取代币/池/风险/报价 → 确认或已授权自动规则 → 交易前校验 → 按链和钱包分配 nonce → 本地签名 → 对应 RPC/发送渠道 → 链上结果 → 账本与订单状态 → 刷新界面/本人通知。

外部数据只作为输入，不允许直接指定任意签名收款地址或绕过本地交易校验。价格、税费、审计与报价应记录来源和时间，过期数据不伪装成实时数据。

全局暂停只阻止后续自动任务，不把已广播交易说成已撤销。是否允许手动卖出需清楚显示，避免把退出通道一起关闭。

## 7. 费用、运行条件与主要风险

| 项目 | 当前/规划的费用判断 |
| --- | --- |
| 平台抽成 | 本人机器人不加平台抽成；Based Bot 官方收费页写每笔 1% [S11] |
| 链上费用 | Gas、DEX/代币税及桥费用仍需支付，不能承诺零总手续费 |
| RPC / 报价 | 现阶段继续免费方案；限流、延迟和接口条款可能变化，不承诺无限额度 |
| 全天在线 | 本机可运行，关机/休眠后本机监控和自动化会停止；服务器属于额外可选运行成本，未获授权不部署 |
| 追踪与历史数据 | 完整历史、实时钱包事件、持有人分布可能需要索引/API 服务；先核实免费能力与覆盖，不虚构全量历史 |
| 社交数据 | X 等平台数据接入方式、权限和价格待该阶段核实；不假定可以免费稳定抓取 |
| 安全审计 | 文档中的合作方服务不是本项目已拥有的能力；检测不等于绝对可卖或不会 rug |
| 网页终端 | 本机私用可不购买域名；公网、数据服务、托管和证书运维的实际成本届时确认 |

预算尚未给出；默认不新增付费服务。出现必须付费的能力时，先提供可审核的服务、用途、费用与免费替代差异，再由用户决定，不自动采购。

最大风险不是页面做不出来，而是自动交易误触发/重复执行、节点延迟造成状态误判、错误链/假币、未知买卖税、跨链中间状态和高频数据不可靠。因此每期必须先验证可重复执行的状态流程，再做真实小额资金验收。

- 本次新增调研文档不需要重跑已经通过且未改变的代码测试；任何后续实现再跑相应检查。
