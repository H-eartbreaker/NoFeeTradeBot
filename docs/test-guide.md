## 1. 测试计划

### 1.1 目标

1. 资金安全：未经确认不下单；重复点击不重复交易；交易结果未知时不自动重发。
2. 私钥安全：私钥不出现在聊天、日志或返回值中；本地文件权限为 600。
3. 白名单：只有 `ALLOWED_USER_ID` 能操作；其他用户的消息和回调被拒绝。
4. 数据正确：金额精度、滑点下限、成本和盈亏计算、账本恢复。
5. 界面：按钮回调数据不超过 Telegram 的 64 字节限制；菜单与功能一致。

### 1.2 范围与层次

| 层次 | 内容 | 对应测试文件 |
| --- | --- | --- |
| 纯逻辑单元 | 工具函数、设置解析、自动规则、盈亏计算 | `util`、`settings`、`auto-rules`、`pnl`、`pnl-card` |
| 交易与账本模块 | 买卖、转账、兑换、授权撤销、钱包保存、账本恢复 | `trade`、`funds`、`approvals`、`ledger` |
| Telegram 交互 | 卡片、确认页、输入、按钮、钱包面板、Logo | `bot`、`wallet-panel`、`positions`、`logos`、`button-icons` |
| 后台监控 | 止盈止损调度、分档、移动止损、全局暂停 | `monitor` |
| 外部真实数据 | 只读冒烟脚本，需要网络，不属于 `npm test` | `scripts/*.ts` |

### 1.3 测试方法

- 框架：Node 内置 `node:test`，断言使用 `node:assert/strict`。
- 依赖：多数测试注入假的链上读取、路由、风控和交易函数，不发送真实交易。
- 临时文件：状态和钱包相关测试使用临时目录，结束后删除。
- 测试入口：以 `package.json` 中的 `test` 脚本为准（当前为 `node --test test/`，本轮确认能发现全部 21 个文件）。运行前请确认它确实会执行 `test/` 下全部 `*.test.ts`，如果不会，改用第 2 节的单文件命令逐个运行。

### 1.4 验收标准（运行后应满足）

- `npm run check` 无报错。
- `npm test` 全部通过，无跳过（`skip`）用例。
- 资金相关用例（`trade`、`funds`、`approvals`、`ledger`、`bot`）全部通过。

## 2. 如何运行

环境：Node 26（与项目一致），在项目根目录运行。

```bash
# 1. 类型检查（开发期间唯一允许的构建检查）
npm run check

# 2. 全部单元和交互测试（不需要 .env，不访问真实链上数据）
env -u SOLANA_PRIVATE_KEY npm test

# 3. 单个测试文件
node --test test/util.test.ts

# 4. 只读冒烟（需要网络，可能需要代理）
NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:7897 node scripts/smoke.ts [链key] [代币地址]
NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:7897 node scripts/ui-smoke.ts
```

注意：
- `scripts/ui-smoke.ts` 会用真实只读数据走卡片和买前确认，但拦截所有 Telegram 消息和交易发送。可以在命令后指定链 key；默认检查四条链。
- `scripts/funds-smoke.ts`、`scripts/latency.ts` 是真实只读查询，不发送交易。
- `scripts/setup.ts`、`scripts/new-wallet.ts`、`scripts/import-wallet.ts` 会生成或导入私钥，**不属于测试，不要在测试流程中运行**。
- 测试中不要使用真实私钥。应使用假私钥，例如 `"0x" + "1".repeat(64)`。

## 3. 测试清单

当前共 21 个测试文件，128 个用例（本轮实际执行确认）。以下 3.1～3.15 为原有用例，新增文件与数量见本轮测试结果。下列要点是根据用例标题整理的摘要，具体断言以测试文件为准。

### 3.1 `test/util.test.ts`（7 个）

- `extractAddress` 提取并转为小写
- `fmtUnits` 格式化
- `pctToBps` 边界
- 滑点输入支持直接数字和百分号，拒绝模糊输入
- `escapeHtml` 与 `errMsg`
- `loadConfig` 默认值与校验
- `State` 仓位成本、规则与旧格式迁移

### 3.2 `test/settings.test.ts`（3 个）

- 自定义金额和比例只接受明确有效的输入
- 新设置兼容旧文件、分链隔离、重启保留，重置不损坏持仓
- 交易池身份包含路由、DEX 和资产，去重且不因报价变化而变化

### 3.3 `test/auto-rules.test.ts`（7 个）

- 固定止盈止损与原有判断一致，止损优先
- 分档止盈逐档触发，每轮只触发一档
- 移动止损从最高价回撤触发，未超过成本时不启用
- 止损先于移动止损和分档止盈
- `hasRule` 只在有规则时返回真
- 解析旧格式、分档、固定止损和移动止损
- 拒绝无效或有歧义的规则

### 3.4 `test/pnl.test.ts`（5 个）

- 加权成本、分批卖出与本金回收分别核算，剩余成本不当作未回收本金
- 旧交易与外部入币成本未知时不虚增收益；完全清仓后的新周期可恢复核对
- 缺失卖出到账不填零，保留剩余成本；失败费用和不完整的 L1 费用单独统计
- 转出代币按分数移走成本但不当作盈利；稳定币兑换可形成成本链条
- 同交易哈希去重，未确认操作不当作成交收益

### 3.5 `test/pnl-card.test.ts`（2 个）

- 盈亏图片输出 720 像素宽的 PNG，并转义代币名称
- 没有可核对持仓、本金未知或数量被省略时仍能渲染

### 3.6 `test/trade.test.ts`（7 个）

- 确认后换池或风控失败，实际交易层不广播
- 确认后的新报价不能低于确认页的最低可接受数量
- 价格在允许范围内变化时收紧构建滑点，保留确认页下限
- 自定义小数卖出比例在交易层按整数基点计算
- 排队期间过期的确认在交易层被拒绝，风控在出队后执行
- 金额卖出使用确认的精确代币数并保留最低输出；余额或价格变化时拒发
- 自动订单排队或准备交易后暂停，买卖发送前再次检查，均不广播

### 3.7 `test/funds.test.ts`（11 个）

- 金额保留币种精度；转账正确编码地址与金额，Gas 预算累计而非每笔重置
- 转账过期、余额不足、费用变高或队列中过期都不广播；成功记录完整币种信息
- 转账回执超时保留 hash，下一次操作不会自动补发
- 稳定币兑换精确授权，旧额度先清零；行情变差不先浪费授权，构建输出不符拒发
- 兑换已成交但 RPC 余额滞后时，不误报为失败或自动重发
- 跨链报价核对来源、目标、收款人、金额和平台费，拒绝多步骤或任意签名
- 跨链状态独立轮询，重启后继续查询已有待到账记录，不重新发送
- 资金输入直接回复，确认页核对收款地址与金额，双击和非白名单不重复提交
- 兑换、跨链均要确认；取消、过期与切换菜单会废弃旧确认
- 提交结果未知或消息发送失败不自动重发，不伪造成交失败
- 报价等待时取消，不会迟到生成可提交的旧确认

### 3.8 `test/approvals.test.ts`（5 个）

- 撤销只向指定代币的指定对象 approve 为零，已有零授权不花 Gas
- 撤销过期或超预算不广播；回执成功但额度未归零时不声称已撤销
- 撤销结果未知时保存 hash 并阻止重发
- 授权列表范围明确，撤销先核对链、钱包、CA、对象；双击和非白名单不重复执行
- 撤销取消、过期或切换菜单后失效；未核对为零的结果明确提示

### 3.9 `test/ledger.test.ts`（7 个）

- 多钱包持仓隔离，旧主钱包格式兼容，同笔成交恢复时不重复记账
- 钱包仅保存在本地，限制文件权限，并避免覆盖其他进程新增的钱包
- 钱包保存遇锁退出，原文件不变
- 账本残缺不静默丢失；pending 经只读回执恢复，成本只更新一次
- 交易回执超时保留 hash，未确认时拒绝再次广播
- 同钱包同链串行，其他钱包的交易不被挡住
- 精确数量卖出按实际分数扣成本，账本恢复时不因百分比取整而多扣

### 3.10 `test/bot.test.ts`（13 个）

- 点滑点后直接回复百分比，分链买卖分别保存
- 滑点错误重试、取消、其他命令和白名单
- 首页和设置有可点击入口；时区验证和显示开关可保存
- 买前确认显示链、CA、名称、池、税费；确认后只执行一次并刷新原卡片
- 取消、过期、设置修改和重启后旧确认都不能下单
- 关闭确认只影响选中链；貔貅风控仍拦截；未知结果明确提示
- 自定义买入保持原链与输入金额；自定义卖出支持小数比例
- 买卖按钮可编辑，旧档位不误买，恢复默认不修改已有仓位
- 输入超时和消息失败不会导致重复交易或误报失败
- 四链卡片能生成，按钮 `callback_data` 不超过 Telegram 长度限制
- 确认后检测变为貔貅或税费变化，阻止下单
- 快速买入默认关闭，开启需确认，且不能绕过买前确认
- 进入 Logo 等提前处理的菜单也会退出资金输入，旧收款步骤不继续

### 3.11 `test/positions.test.ts`（4 个）

- 目标卖出按最小接收量计算；全仓不足时拒绝，不自动全部卖
- 持仓页分开显示已实现、浮动和 Gas；本金卖出先确认并只执行一次
- 按金额卖出直接回复，非法输入可重试；取消、切换菜单和过期不提交
- 盈亏图片按钮发送 PNG 说明，不触发交易

### 3.12 `test/wallet-panel.test.ts`（6 个）

- 钱包入口、充值网络和默认钱包切换，重启仍记住选择
- 切换钱包让旧买入确认失效；新卡片和自定义输入绑定各自钱包
- 创建前确认、双击去重、取消、过期和非白名单均不会额外创建钱包
- 创建保存失败和余额查询失败给出明确结果，不切换钱包
- 历史按钱包和链隔离，真实金额与 Gas 区分，分页不重复，待确认不误报成功
- 本地导入入口不接收聊天私钥；非交互导入在读取配置前退出

### 3.13 `test/logos.test.ts`（7 个）

- 从 UTF-16 表情位置识别四条链和原生币 Logo，忽略未支持的链
- 导入先预览，白名单限制；确认只保存图标，不保存转发的余额与地址
- 截图中的链名都能收藏，名称别名归一，未知链不会错误归到罗宾汉
- 一次导入收藏未启用的链，重启后能复用，二次导入保留已有图标
- 取消、超时和其他命令不会误保存；截图或无表情消息继续提示
- 四链文字和按钮都可用自定义 Logo；关闭后只显示名字且保留配置
- Telegram 明确拒绝表情时回退为文字，网络错误不重发

### 3.14 `test/monitor.test.ts`（5 个）

- 止盈止损每 3 秒调度，停止后不再调度
- 分档止盈按顺序卖出部分仓位，成本和进度同步，重复检查不重复卖
- 移动止损记录最高价，从高点回撤超过阈值时全部卖出
- 全局暂停时不卖出，恢复后按规则执行

## 5. 未覆盖项及原因

| 未覆盖项 | 原因 |
| --- | --- |
| Solana 真实签名广播、真实到账与费用 | 本轮只用模拟依赖和未签名构建；真实资金验收未授权。 |
| 追踪钱包全部分页/50 地址上限 | 已测基本管理流程，完整压力和边界仍可补。 |
| 自动单所有网络故障和长期运行组合 | 已覆盖核心调度、预算、取消和恢复；没有连续运行数天或进行真实成交。 |
| 外部 API 客户端（`token.ts`、`honeypot.ts` 等） | 依赖第三方接口。需要录制或模拟响应，尚未补齐。 |
| 网络层（`http.ts`、`native-fetch.ts`） | 依赖代理和网络环境，没有模拟。 |
| 命令菜单与启动入口（`menu.ts`、`index.ts`） | 依赖 Telegram API 和进程启动，没有模拟。 |
| 真实链上交易 | 测试不允许花真钱。真实交易只能在用户明确给出链、代币和金额后，手动验证。 |

## 6. 验证边界

- 测试通过只说明断言覆盖的行为，不能当作全部功能或真实成交保证。
- 本轮未使用 Telegram 真账号做全菜单人工验收，也未为了测试重启/停止真实机器人。

## 7. 给后续 Agent 的 Solana 测试建议

本轮已实现其中多数核心场景；未覆盖组合仍可继续补齐。全部使用假 RPC 和假私钥，不要使用真实钱包：

1. `sol-wallet.ts`
   - 生成后写入 `.env`，权限为 600，且 `SOLANA_PRIVATE_KEY` 行格式正确
   - `.env` 已有 `SOLANA_PRIVATE_KEY` 时拒绝，不覆盖
   - 空的 `SOLANA_PRIVATE_KEY=` 行被清理

   - 私钥不出现在返回值、日志、错误或聊天；生成接口只返回公开地址
   - 格式错误的私钥（非 base58、长度不是 64 字节）在启动时报错
2. `sol-chain.ts`
   - `holdings` 按 mint 聚合两个 Token 程序的账户，跳过余额为 0 的账户
   - `mintInfo` 拒绝 owner 不是两个 Token 程序之一的地址，拒绝非 mint 账户
   - `quote` 和 `swapTransaction` 在错误响应时抛出可读错误
   - `isSolanaAddress` 边界：31 和 45 字符、包含 `0`、`O`、`I`、`l` 的字符串应拒绝
3. `sol-trade.ts`
   - `awaitLanding` 四个分支：确认、链上错误、过期未上链、超时待定。用假 RPC 控制区块高度和签名状态
   - 过期判断先读区块高度再读签名状态
   - `serial` 同一钱包按顺序执行，不同钱包互不阻塞
   - 买入余额不足（需保留 0.01 SOL）时拒绝；卖出时 SOL 不足 0.005 SOL 时拒绝
   - 卖出百分比按整数计算，100% 使用全部余额
4. `sol-panel.ts`
   - `parseSolAmount` 边界：`0`、`0.000000001`、`100`、`100.000000001`、`1e3`、`-1`
   - 回调数据长度不超过 64 字节（包括带金额版本号的买入按钮和小数卖出比例）
   - 确认页 60 秒过期后，点击确认不执行交易
   - 自定义输入中粘贴 `0x` 地址时退出 Solana 输入，提示核对当前链；Solana 模式下不能进入 EVM 买卖
   - 非代币地址给出明确提示，不进入买卖流程
5. `state.ts` 和 `config.ts`
   - `solanaSlippageBps` 缺失或不是整数时默认 100
   - `SOLANA_RPC_URL` 未设置时使用默认 RPC
